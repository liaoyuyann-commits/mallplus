# Project Brief — 项目定位

## 一句话愿景
MallPlus：在开源微服务商城（mall-swarm）上二次开发「多级缓存治理 + 购物车双层存储」，作为 Java 后端面试的深度项目。

## 目标用户
- **面试官**（Java 后端岗位）：需要看到"能读懂开源项目、能借助 AI 设计业务模块、了解从想法到落地流程"的候选人
- **作者本人**（Java 基础 + 算法，C 型学习者）：通过协同开发真正理解每个设计决策

## Must Ship（v1 必做，6 个 P0）
1. 二级缓存治理（Caffeine 本地 + Redis 二级）覆盖商品详情/首页，目标 MySQL 读压降 80%+
2. 缓存击穿防护（Redis SETNX 互斥锁）
3. 缓存穿透防护（Guava 布隆过滤器 + 空值缓存）+ 随机过期防雪崩
4. 购物车双层存储（Cookie 临时车 ≤3KB + Redis Hash 已登录车），查询/变更 <20ms
5. 登录异步合并（RocketMQ，mergeId 幂等）
6. 缓存一致性：admin 改商品 → RocketMQ → portal 清本地+Redis 缓存

## Not in v1
- 产品内 AI 交互（预留扩展口，功能接口与实现解耦）
- Elasticsearch 搜索深度改造
- 秒杀/优惠券/分销
- 真实上线部署/真实收款
- Redis 购物车异步落 MySQL 兜底（延伸点，只在面试讲解时提）

## 成功信号
- 代码可编译 + git 提交完整（今晚）
- 两个功能能独立讲清 Why/How/Trade-off/Pitfall（2 周内）
- 扛住模拟面试追问

## 原则
- 不改框架、不动原版 RabbitMQ、不加表
- 每个新概念先解释再落地，注释讲"为什么"
- 面试讲稿 = 每个功能块的"问题 → 方案 → 权衡 → 坑"
